## 公开范围

此仓库保存通用 FAQ、提案、维护说明及模拟 RFQ 示例。真实客户 RFQ、联系人、议价和项目专有资料保留在 Odoo / Nextcloud，不提交到公开仓库或公开 Issue。引用证据时填写内部编号，或提供经处理的公开材料；不要把私有链接的访问凭据写入正文。

## 修改和审批

1. 团队或外部贡献者使用 [FAQ 修改建议表单](https://github.com/ReZ-TI/faq/issues/new?template=faq-change.yml) 提问。
2. 维护者归类、去重并从新分支提交 PR；外部贡献者可通过 fork 提交。
3. Kelvin 审阅答案、证据、适用范围和译文。核验不足时继续保持 draft。
4. main 要求通过 PR 更新，至少一个批准，并要求 CODEOWNERS 审核；新内容推送后需重新审核。以仓库实际规则状态为准。
5. 不自动批准或合并。不通过修改保护规则绕过内容审核。

GitHub 不允许 PR 作者审批自己的 PR。本次样例以 Kelvin 账号创建，因此保留待审核状态；正式由其他作者提交最终版本，再由 Kelvin 审批。负责人如参与改稿，也应由符合规则的独立审阅者核验。

## 正式答案与发布

GitHub 默认分支保存维护规则、来源快照及经过实际审核的正式答案。当前答案样例仍在 PR 中。

只有 status 为 approved、audience 为 public_candidate、且有真实 PR 审核记录的最终答案，才进入网站发布复核。中文、英文成对检查。官网发布人与时间、对应 PR / commit 另行记录。

Odoo 仅发布获准公开的答案；Nextcloud 保存原始资料，可保留只读导出副本；Dify 等知识库未来按批准版本同步。合并不自动改变这些系统。
