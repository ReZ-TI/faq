# 维护与发布

[返回 FAQ 首页](README.md)

## 内容维护

团队通过 Issue 提交通用问题，通过 PR 修改中英文 FAQ。Kelvin（kelvinchen1119）负责确认业务口径、适用范围与译文；未确认的内容保持 `draft`，确认后记录审核人和日期，并标记为 `approved`。

正式问答仅保留对客答案、适用条件和语言导航。修改理由与审核过程保留在 PR 记录中，原始依据在受限渠道核验。公开仓库不放客户身份、原始邮件、询价定位编号或项目报价。

## 合并

main 通过 PR 更新。内容负责人明确同意后，维护者按仓库规则合并；不在未获同意时自动批准或合并。

GitHub 不允许作者为自己的 PR 点 Approve。当前 kelvinchen1119 已配置个人手动合并例外，可在明确确认内容后合并自己的 PR；仍须经过 PR，不能直接推送 main。其他贡献者按仓库实际保护规则提交审核。

## 发布

`status: approved` 且 `audience: public_candidate` 的答案可进入官网发布流程。中文与英文成对发布，并记录官网地址、发布时间及对应提交。

GitHub 合并与 Odoo 官网发布分别执行；当前未配置 Odoo、Nextcloud 或 Dify 自动同步，也未配置定时整理任务。
